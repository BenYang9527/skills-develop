# 审查规范生成指导

> **使用边界**：仅供初始化／升级。先读 [派发约定](init-agents.md#2-派发约定) 与 [共同生成方法](init-project-docs.md)，按主 Agent 指定的输入、文件范围和授权处理。

## 1. 调查与填充

从 Git 和项目规则确认保护分支、提交策略、团队审批人数；从项目脚本、CI、测试与编码规范核对命令和实际入口。项目数值门槛引用 verification.md，不另设标准。

按 [code-review.md](../assets/project/docs/code-review.md) 填写适用的审查范围及项目要求。保留 §1 的独立追踪、疑点比较与冲突反馈方法，不能简化成“检查可读性”的勾选项；编码审阅依据引用 coding-style.md，不重新生成一份顶层清单。

项目要求的人工 Reviewer、审批与合入规则继续保留。独立审查、项目审批与有效提交授权分别核对，不为个人项目额外固定一次最终人工确认。

## 2. 旧入口迁移

完整读取旧 **.harness/review.md**，融合独有有效规则，按升级确认删除旧入口并修复引用。已有任务 Review 记录保留，不重编号。
