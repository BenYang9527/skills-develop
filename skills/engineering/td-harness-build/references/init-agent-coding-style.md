# 编码规范生成指导

生成或更新项目 **.harness/docs/coding-style.md** 时使用，保留对应模板的章节结构。

> **使用边界**：仅供初始化／升级。先读 [派发约定](init-agents.md#2-派发约定) 与 [共同生成方法](init-project-docs.md)，按主 Agent 指定的输入、文件范围和授权处理。

## 1. 核对项目事实

1. **确定适用范围**：核对语言、版本、依赖、代码目录与已有规范。Go、JS/TS、Python 按需读取对应 language-profiles；其他语言沿用项目已有工具，不强套 Go。框架确认后才读取相应参考。
2. **核对工具配置**：检查格式化、Lint、安全工具，以及实际 core.hooksPath、Hook 配置和 CI，确认命令是否被调用。安装工具或写下命令，不等于启用了门禁。

保留有效项目约定，不照搬历史坏写法。缺少规范时，依据实际语言和框架形成少量可执行约定；冲突或改进按授权处理。

## 2. 填写编码规范

### 2.1 章节填写对照

| 目标章节 | 填写内容 |
|---|---|
| **项目约定与工具** | 有效约定、实际工具与执行入口；登记项见 §2.2 |
| **命名与注释** | 仅保留项目语言；沿用模板的顶层步骤编号、必要说明、可读性与接口设计标准，不增加逐层解释 |
| **错误、资源与并发** | 按语言及版本适配错误传播、资源释放和共享状态保护 |
| **安全编码** | 输入与操作边界、凭据、密码、安全随机数及传输保护；日志引用 logging.md，接口引用 api-standards.md |
| **检查与例外** | 区分工具检查和独立审查；执行结果及授权边界见 §2.2 |
| **正反例** | 文末保留最小代码对照，注明适用条件与改善点；适配项目语言，同类合并或替换，不扩成多语言规则库 |

### 2.2 规则与接入

工具登记、可读性、参数提示、语义审查与例外规则按 [coding-style.md](../assets/project/docs/coding-style.md)；固定命令与数值门槛的归属按 [04 Docs §1.2](../assets/workflows/development/04-docs.md#12-内容与职责)。

重复检测接入方法见 [setup-checks.md §4](setup-checks.md#4-重复代码检测jscpd)，执行参数依据实际配置。按语言和授权适配参数等检查，写清命令与配置，不预设所有语言共用工具。工具安装、配置修改与既有代码重构分别核对授权。

## 3. 交付核对

交付前核对命令、章节引用、适用语言及框架能力，Source 与核对时间仅填写实际证据。初始化／升级按 [升级规则](upgrade-project.md) 融合既有内容。

纯文档项目或技术栈未定时，保留适用骨架并说明缺口，不编造工具或代码规范。
