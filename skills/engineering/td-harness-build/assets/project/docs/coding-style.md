## 2. 命名与注释

### 2.1 命名与语言约定

名称表达职责，给有业务含义的常量命名，保留通用缩写。按项目配置选择适用的语言约定。

| 语言                   | 默认约定                                                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Go                     | 包名简短小写，文件用 `snake_case`。导出名用 `PascalCase`，其他名称用 `camelCase`。接收器命名一致，点导入和副作用导入需有明确用途。 |
| JavaScript／TypeScript | 变量、函数用 `camelCase`，类型、类用 `PascalCase`。                                                                                |
| Python                 | 模块、函数和变量用 `snake_case`，类用 `PascalCase`，常量大写。                                                                     |
| Java／C++ 等           | 按项目配置约定命名、可见性及 import。                                                                                              |

### 2.2 文档注释

导出符号按该语言的文档格式说明用途、参数约束、返回值和必要异常语义。Go 注释以符号名开头。删除无用途的注释代码，确需暂留时说明原因和清理条件。

### 步骤说明（建议）

注释语言沿用项目约定，优先解释目的、约束和时序。复杂流程可按阶段分块，编号可选。生成代码通过生成入口更新，历史代码的注释按本次改动需要处理。

### 2.3 可读性与接口设计

- **Deep Modules** 用简单接口封装完整职责。提取模块时，检查调用方少理解了哪些参数、时序或错误处理。复杂度超标时优先简化控制流或按职责拆分，避免只增加跳转。
- 遵循 **DRY**，同一条业务或协议规则只维护一份。用「规则变了，这几处是否必须一起改」判断是否共用。
- 遵循 **YAGNI**，只为当前需求引入能力和抽象。新增抽象时说明它解决的当前问题。
- 优先用早返回和命名条件表达主流程。参数超过 5 个时检查调用方负担，此项为审阅提示。需要处理未知值的 `switch` 明确兜底。
- 在 **Trust Boundary（信任边界）** 校验输入，在持有状态的模块检查业务不变量。内部调用可依赖上游契约在当前路径已保证的条件。新增校验须有需求、契约或安全依据。例如，SDK 校验回调格式后，资源归属仍由有权判断的一层确认。

## 3. 错误、资源与并发

### 3.1 错误处理

处理或传播错误，确需忽略时说明理由。异步失败须有处理路径，宽泛捕获只用于明确的边界。保留定位所需上下文，公开错误按契约返回，禁止泄露敏感内部信息。敏感日志按[日志规范](logging.md)处理。可恢复错误走正常失败路径。

Go 的 `error` 放最后返回，需要保留错误链时用 `%w`。英文错误消息通常小写开头且不加末尾标点。普通业务失败返回错误。

### 3.2 资源生命周期

获取资源后明确所有者与释放方式，覆盖成功、异常和提前返回。按语言选择释放机制，如 Go 的 `defer`、Python 的 `with`、Java 的 try-with-resources 或 C++ 的 RAII。循环内获取的临时资源按轮释放。

### 3.3 并发与数据语义

对共享可变状态做同步或隔离，明确锁顺序和线程、协程与异步任务的退出、取消方式。闭包捕获按项目语言版本核对。空值和空集合按接口契约处理。Go 的 map 并发写入须保护，channel 由明确的所有者关闭一次。

## 4. 安全编码

### 4.1 外部输入与操作边界

- 按契约校验外部输入的类型、长度、范围和格式。动态标识符用受控映射或允许列表。
- SQL 值用参数化查询。命令用结构化参数 API，核对参数语义，禁止把不可信输入拼入 Shell。
- 受限文件操作须验证实际路径边界，处理符号链接及竞态。简单的字符串前缀比较不足以证明路径受限。
- 输出按 HTML、属性或 URL 上下文编码。不可信富文本用成熟工具清洗。
- 外部输入能影响请求目标时，限制协议与目标，校验解析结果、实际连接地址和重定向目标，覆盖 IPv4、IPv6、回环、内网与云元数据地址。内部服务仅经项目允许的入口访问。
- 处理不可信 XML 时禁用 DTD 与外部实体。禁止将不可信数据反序列化为任意可执行对象。

项目如有 API，访问控制、浏览器入口和限流见 [API 规范 §4](contracts/api-standards.md#4-安全与访问控制)。

### 4.2 凭据、密码与随机数

真实凭据使用项目配置，禁止硬编码或提交。需要存储密码时，使用带盐、可调成本的密码哈希。加密、摘要和签名使用成熟库，敏感数据加密采用项目获准的方案。新安全用途禁用 DES、3DES、MD5、SHA-1 和 RC4。密钥、Token 等使用密码学安全随机数生成器（CSPRNG），Go 使用 `crypto/rand`。

### 4.3 传输安全

敏感数据传输使用 TLS 1.2 或以上，优先 1.3，并验证证书和主机名。隔离测试的例外须获批、限范围，并隔离于生产配置。

## 5. 检查与例外

按[验证规则](verification.md)运行检查并记录实际结果、失败和复验。例外先按授权获批，在任务记录或 PR 写明规则、理由、影响和缓解方式。获批后才在限定范围内抑制规则，由 Reviewer 核对。

## 6. 正反例

导出调用方只决定范围和字段。

- **反例** `create({ range, columns, workerCount: 8, retryLimit: 3 })` 把并发和重试交给调用方配置。
- **正例** `create({ range, columns })`。并发和重试由导出模块负责。
