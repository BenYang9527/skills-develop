# Backlog · 需求池

保存后续需求与想法。纳入本次交付前，仍须明确范围并确认需求与 AC。

## 1. 后续需求清单

| 编号 | 需求 | 类型 | 背景与期望 | 优先级 | 状态 | 依据 |
|---|---|---|---|---|---|---|

有需求时再添加条目；编号保持稳定。

- **需求**：用短句记录想解决的问题或想增加的能力，可以保留用户的原始表达。
- **类型**：缺陷、体验优化、新需求；尚不能确定时填“待判断”。
- **背景与期望**：已知时补充哪里不方便、希望有什么改善；不清楚就留待讨论，不编造。
- **优先级与状态**：按实际决定填写；优先级尚未确定时写“待定”，需求尚未澄清时写“待讨论”。
- **依据**：已确认的详细要求链接 PRD 对应章节；暂缓事项的讨论链接 [Discussion Pool](03-discussion-pool.md) 的对应条目。迁入后续轮次时更新引用。

表格用于浏览和安排工作。讨论细节在讨论池按对应编号保存，本表保留摘要和入口；已在 PRD 中的要求正文不重复抄写。

需求池允许模糊想法，不要求提前写成完整需求或 AC。选入本次交付前，再澄清具体行为和完成标准。
