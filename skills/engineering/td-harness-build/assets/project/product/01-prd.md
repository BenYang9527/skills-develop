# PRD · 产品需求

记录产品服务谁、解决什么问题，以及已经确定的功能和约束。标明哪些已实现、哪些尚未实现；每次交付的实施范围以该次 Delivery Requirements 和 AC 为准。

## 1. 用户与问题

谁会使用产品？在什么场景下遇到了什么问题？只写已有依据，未知项标为待确认。

## 2. 产品目标

产品希望给用户带来什么改善？

## 3. 功能与约束

按用户目标组织已确定的功能，保留必要的业务规则、边界和异常处理，包括尚未安排开发的要求。标明实现情况；确认需求不等于已经交付。

## 4. 相关资料

- **相关依据**：按需记录来源与决定依据；产品要求及必要理由在本文说明完整，不依赖讨论池或旧任务正文才能理解。维护规则见 [读取与更新边界](../docs/clarify.md#23-读取与更新边界)。
- **后续需求**：[Backlog](02-backlog.md)。
- **外部维护位置**：用户指定后填写；维护方式见 [外部资料维护规则](../docs/clarify.md#24-外部资料)。
