# 05. Review — 独立验收

> **执行角色**：Reviewer；独立性、写入范围及返工见 **.harness/agent-roles.md**。
> **方法**：语义审查见 **.harness/docs/code-review.md**；检查选择、通过标准及证据要求见 **.harness/docs/verification.md**。

## 1. 结论与范围

- **发现数量与结论**：🔴 阻断／🟠 警告／🟡 Nit 各多少；通过／不通过／待验证。
- **Reviewer／时间、审查版本及差异范围**：包括未提交差异和实际核对位置。
- **关键行为与职责定位**：简述独立追踪的行为及负责位置。

需求与 AC 由 **00-overview.md §3** 定位；方案、自测和文档更新分别引用 **02-plan.md、03-implement.md、04-docs.md**。

## 2. Findings（审阅发现）

按 **code-review.md §2–3** 核对需求与规范，记录有具体依据的发现。同类问题归并；普通修复、分歧及复验更新原条状态。

有记录时填写下表并替换示例行；无适用项时用一句话说明并删除表格；必要项未执行仍须记录缺口。

| #                  | 等级    | 位置及需求／规范依据   | 问题、触发条件与后果             | 处理决定及复验依据   |
| ------------------ | ------- | ---------------------- | -------------------------------- | -------------------- |
| 示例（填写时替换） | 🔴 阻断 | AC-002；编辑器保存入口 | 保存中仍可再次提交，可能重复写入 | 待修复；复验尚未执行 |

## 3. 实际验证

1. **核对检查清单。** 按 **02-plan.md §6.1、§6.4** 确认 AC／AT 的验证范围（本 Task 交付或完整 AC）、检查入口和通过条件。涉及 IT 时按 **§6.3** 核对计划场景。对照 **.harness/docs/verification.md §1–2** 核对适用门禁和质量指标（覆盖率、圈复杂度、CRAP 等）。
2. **执行或复用。** 按 **.harness/agent-roles.md §1.1** 亲自验证关键场景。其余检查按 **verification.md §3.1** 执行，或复用适用于当前版本、环境和范围的 Owner 自测并写明依据。记录影响结果的环境、真实依赖和数据。
3. **记录结果。** 按 **verification.md §3.2** 填表，逐项写实际结果，含所选质量指标的实测值或观察结果。一次执行覆盖多项时共用证据。合并说明确实不涉及的项，未完成的必要检查按 **verification.md §3.3** 记入 §4。
4. **保留复验记录。** 在对应检查或发现中记录首次失败、原因、修复差异、复验版本和结果。记录必要的数据及临时资源清理结果。

填写时替换示例行。确无适用检查时，用一句话说明依据并删除表格。

| 检查／用例／AC 与范围            | 证据来源及复用依据 | 命令或操作、实际结果与证据位置       | 状态 |
| -------------------------------- | ------------------ | ------------------------------------ | ---- |
| 示例 · AC-002 保存失败后保留输入 | Reviewer 执行      | 模拟保存失败，核对表单输入仍保留     | 通过 |

## 4. 验证缺口与必要处置

- **未解决项、必要验证缺口及剩余风险**：说明影响、原因、补验责任与恢复条件；无则写“无”。
- **实质分歧或获准例外**：有时记录依据、决定及确认来源。
- **重要失败复盘**：无重要失败／Owner 已登记的失败记录链接，Reviewer 核对。
- **授权核对**：按 **AGENTS.md §2.6** 记录项目要求的审批、实际获准的提交操作，以及用户条件在当前版本是否满足；缺少时写明等待项。

必要检查与阻断项完成处置后方可给出通过结论；独立审查通过、项目审批及有效提交授权条件满足后，进入 **06-submit.md**。

Owner 更新 **00-overview.md** 的进度、实际时间与累计验收轮次，Reviewer 核对。提交后返工的记录更新按 **06-submit.md §4** 的冻结范围执行。
