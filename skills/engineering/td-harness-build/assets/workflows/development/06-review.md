# 06. Review — 独立验收

> **执行角色**：Reviewer；派发与权限见 **.harness/agent-roles.md**。
> **用途**：独立语义审阅：核对最终改动、需求与验收条件（Acceptance Criteria，AC）及验证证据，判断设计与阅读负担，记录发现、处置、适用审批与提交授权。
>
> **方法**：按 **.harness/docs/code-review.md §1**，先独立追踪关键行为，再核对作者交接及 **04-verify.md** 的结果；有疑点才比较替代结构，不默认重跑全部验证，不复制长期检查清单。

## 1. Review 概览

- **独立审阅者（Reviewer）／会话**：
- **Review 时间**：
- **PR／MR 入口（已有时）**：
- **审查版本、差异范围与实际核对位置**：
- **关键行为与职责定位**：简述实际追踪的行为及负责位置，不复述整段实现。
- **实际改动规模**：

按批准的比较基准统计文件数及增删行数；手写实现、测试、文档和生成代码分开记录。审查范围包含接口与代码可读性，实际核对位置写明文件或函数；具体标准见 **.harness/docs/code-review.md**。

需求与 AC 从 **00-overview.md §3「需求与验收入口」** 读取；方案、验证和文档更新分别见 **02-plan.md、04-verify.md、05-docs.md**。

## 2. 作者交接

只摘要本次审阅重点，详细记录引用对应章节。

- **范围与重点**：本次改动边界、需要特别核对的实现或项目规则。
- **验证与缺口**：引用 **04-verify.md** 的结论，说明未验证项及原因。
- **文档与风险**：引用 **05-docs.md** 的更新记录，说明剩余风险。

## 3. Review Findings（审阅发现）

按 **.harness/docs/code-review.md** 判断问题及严重度。每项写明具体位置和需求、规则或风险依据；未发现问题时写“无”。

| # | 严重度 | 文件／行号 | 问题描述及依据 | 建议 | 处理状态 | 复验／复审依据 |
|---|---|---|---|---|---|---|
| 1 | 🔴 高／🟠 中／🟡 低 |  |  |  | 待处理／已修复／不采纳／批准例外 |  |

**不因工具通过就忽略分层错误或无效断言，也不凭“太长”“更优雅”阻断。** 不采纳或批准例外的理由记入 **§4「讨论与决议」**；修复项填写复验／复审依据。

## 4. 讨论与决议

记录审阅意见存在分歧、不采纳或申请例外时的决定及依据。普通修复记录在 **§3「Review Findings（审阅发现）」**；本节不重复。

|---|---|---|---|---|
|  |  |  |  |  |

修正后，重新检查受影响的部分并交独立 Reviewer 复审，不能沿用修改前的通过结论。

如果用户原先说过“满足这些条件后可以提交”，还要核对修改后是否仍满足这些条件。超出批准范围或需要改变 AC 时，按 **AGENTS.md §2.6「用户确认」** 处理。

## 5. 复盘

检查本轮是否出现值得记录的失败；判断范围及复盘方法见 **.harness/docs/failures.md**。详细复盘写入该文件，本节只记录结论与链接。

- **复盘结论**：无重要失败／已记录。
- **失败记录链接**：

提出改进建议不代表已经实施。修改 Harness 须在已有授权范围内；超出范围时，按 **AGENTS.md §2.6「用户确认」** 处理。

## 6. 最终结论与授权核对

- **独立 Review 结论与最终审查版本**：
- **未解决问题与已批准例外**：引用 §3、§4 对应记录。
- **项目要求的审批与结论**：项目要求人工审批时写明审批人、范围和版本；不涉及时说明依据。
- **Submit 授权来源与范围**：填写实际获准的操作，如 commit、push、创建 PR。
- **用户要求的提交条件**：例如“检查和审查通过后可以提交”。逐项记录当前版本是否满足；没有额外条件时写“不涉及”。

按 **AGENTS.md §2.6「用户确认」** 核对并填写以上各项；缺少审批、授权或条件未满足时，记录具体等待项。

## 7. 完成检查

提交后返工时，以下记录更新项按 **07-submit.md §4** 的冻结范围执行。

- [ ] 独立 Reviewer 已核对实际改动、接口与代码可读性、项目规则及验证充分性
- [ ] 阻塞问题已修正复验，其他问题有明确处置
- [ ] 重要失败已复盘并登记入口；没有则写明无重要失败
- [ ] 独立结论、项目要求的审批及 Submit 授权已分别核对，缺少授权或条件未满足时已说明等待项
- [ ] **00-overview.md** 的开发进度与时间记录已更新

独立审查通过、项目要求的审批完成且有效授权条件满足后，进入 **07-submit.md**，仅执行已授权操作。
