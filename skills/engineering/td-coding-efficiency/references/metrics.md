# 指标口径与报告数据

## 时间

- **总跨度**：明确起止事件之差，旁注事件及范围。Git 提交时间是事件，不是命令退出时间。中途睡觉不改变跨度。
- **可观察执行时间**：有起止证据的实际活动区间并集，主控、子 Agent 和工具重叠只计一次。另报覆盖范围；缺少活动边界时为未知。用户睡觉期间 Agent 仍可能工作。
- **阶段窗口合计**：阶段记录中有效起止窗口的并集，可能包含等待。以任务执行时的 Overview 和项目流程版本确定阶段的编号、名称和顺序。验证若属于某个阶段，就随该阶段记录。Overview 的导航与汇总行不计入阶段。
- 有返工时保留首轮与返工，计算各阶段内部并集。跨阶段重叠时，全局合计再取并集。只有阶段边界完整且范围一致时才报完整合计。
- 显式等待按证据标注；没有事件的空档保持未知。CLI 自报 duration 与消息首末时间分别保留原义，不能直接替代活动并集。只缺一个边界也不能按零计算。

## Implement 并行

对照 Plan 工作块与实际业务改动归属，区分业务实现和协议调查、测试设计、审查等辅助工作。模型替换、角色交接和多个会话不能单独证明并行；确认同时执行需活动区间证据。没有可比串行基线时，不报告净节省时间或提速倍数。

## 用量与费用

每组数据保留角色、模型、会话／计费段、时间范围和来源，先核实当前日志格式的计数语义。累计快照在同一计费段取末值，增量记录按唯一事件去重求和；重置或恢复后的段边界不明时分开列，不能硬加。父级已包含子 Agent 时只计一次，账单和日志覆盖同一调用也只计一次。

区分缓存输入、非缓存输入、输出；reasoning 等子集不能再次相加。缓存读写是否已包含在 input 中，以实际格式为准。不能确认分解时展示原字段，合计未知。只覆盖部分记录就注明部分，不冒充全任务。

实付账单与价格估算分开，保留币种、价格依据和覆盖范围。不同币种不直接相加；未知价格或不完整覆盖时，总成本未知。Token 数量、缓存命中率与生产率分别判断。

## 数据契约

渲染器只读已核对的 JSON。数值可为 **null**，表示未知；已知为零填写 0。所有展示字段都是纯文本，不支持 HTML。字段如下：

```json
{
  "title": "任务名 · 效率一览",
  "scope": "本次交付的边界",
  "outcome": "交付结果及尚未通过的验收边界",
  "times": [
    {"label": "总跨度", "seconds": null, "note": "起止事件与范围"},
    {"label": "可观察执行时间", "seconds": null, "note": "活动区间覆盖情况"},
    {"label": "阶段窗口合计", "seconds": null, "note": "完整性及等待边界"}
  ],
  "phases": [
    {"number": "01", "label": "调研", "seconds": null, "note": "起止记录缺失"},
    {"number": "02", "label": "交付", "seconds": null, "note": "首轮与返工窗口"}
  ],
  "parallel": ["计划工作块、实际业务实现及辅助工作的比较"],
  "usage": ["按角色／模型的用量、覆盖范围和缓存口径", "账单实付与估算分别列示"],
  "bottlenecks": ["已知阻塞、返工及证据边界"],
  "bad_taste": [],
  "unknowns": ["影响判断的数据缺口"],
  "sources": [{"id": "E1", "path": "实际证据路径", "locator": "行号、事件 ID 或字段", "supports": "支持的数字或判断"}]
}
```

**times** 固定为上面三项。**phases** 按任务流程顺序填写，`number` 为阶段编号且在本报告内唯一，`label` 为阶段名称。阶段已知但缺时间时保留该行并用 `null`。未取得阶段清单时填空数组并在缺口中说明。各阶段使用同一报告范围。重渲染旧底稿时按原任务流程补齐 `label`。

其他列表允许为空。Bad taste 每项写明观察、影响和建议。正文数字和重要判断用 **[E1]** 等编号指向 sources。HTML 明细保留证据来源，SVG 用编号与简短说明指向底稿。

## HTML 展示字段

有证据时，在上述 JSON 增加以下字段。原有字段仍可用来生成报告。

| 字段 | 填写规则 |
| --- | --- |
| `takeaway` | 一句效率结论，和交付结果一起显示在首屏 |
| `timeline` | 按时间排序的关键事件。每项填写 `label`，可填写显示用时间 `at`、证据说明 `note` 和强调标记 `highlight: true` |
| `incidents` | 其他阻塞卡片。每项填 `label`、关键观察 `value`、处理结果 `result` 和证据边界 `note`。填写后由这些卡片承载未在时间线上呈现的阻塞，留空时显示 `bottlenecks` |
| `token_usage` | `total` 为已核实的 Token 总数。 `coverage` 写明总数覆盖范围。 `cost` 写明有据可查的实付或估算，并区分两者，缺少依据时省略。 `roles` 可填写角色明细 |
| `token_usage.roles[]` | 每项填写 `role`、已核实的 `tokens`，可填 `model`、`responses`、`cached_input`、`uncached_input`、`output`、`reasoning`。计数为非负整数或 `null`。推理用量是输出的子项 |
| `phases[].tokens` | 可核实、与 `token_usage.total` 同口径且互不重叠的阶段用量。不同口径或缺少依据的阶段填写 `null` |
| `phase_columns` 与 `phases[].records` | 并列对照多个 Task 时，填列名数组，并在各阶段按列顺序填记录数组 |

条形图以已核实的总量为分母。已知分组只覆盖部分总量时，剩余部分标为「归属未知」。缺少总量或分组依据时显示占比未知。阶段彩虹条按流程顺序排列并突出实现。

底稿可附去重过程、时间区间和计算式。总量和阶段窗口由分析者核对。
