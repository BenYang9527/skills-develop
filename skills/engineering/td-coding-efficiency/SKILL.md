# Coding 效率评估

让人快速判断交付结果、主要耗时和可观察的返工。默认交付一份离线 **HTML** 报告。

## 一、确定范围

默认评估当前整场对话，从对话开始统计至本次评估请求，包含关联的 Task 和委派执行。用户明确限定范围时按指定范围统计。

定位对应会话、阶段记录、Git 事实及关联的运行日志和账单，沿用项目读取权限。恢复分析时复用已有入口，无法定位才询问。

记录本次分析所用文件及证据位置。日志只提取必要字段，凭据、原始提示词和无关项目内容留在原处。分析不启动模型任务，也不修改项目代码、Harness 或模板。

## 二、核对数据

读取 [指标口径与报告数据](references/metrics.md)，建立带来源的事实底稿，再填写报告数据。

先核对阶段记录与运行日志是否属于本次统计范围。时间、累计用量、费用分别按该文档去重。缺项写 **未知**，冲突保留并说明。数据不足时照常交付有限结论，并指出补齐判断所需的最小信息。

## 三、形成判断

首屏写明统计范围、实际证据覆盖、交付结果和验收边界，并给出一条效率结论。按时间列关键事件，再显示关键耗时和已记录 Token。明细依次展开其他阻塞、精确用量、阶段记录与实现分工。阶段漏记保留为未知，优先引用已有记录中的明确时间点。

**Bad taste** 只列本次新增、证据明确且影响效率的观察：事实 → 影响 → 轻量建议。已确认处理的事项不重复提案，用户排除的事项不纳入；没有新观察时写“暂无新增”。推测原因单独标为待验证，不把发现信号写成已证实的因果或改善收益。

本报告提供效率事实与观察；需要追究原因、改变协作规则或验证改进效果时，再使用 **td-coding-retro**。评分仅在用户要求且已有明确判据时给出。

## 四、生成与交付

按照[数据契约](references/metrics.md#html-展示字段)填写 JSON，再生成报告。

```bash
python3 <skill-dir>/scripts/render_html.py <report-data.json> --output <Downloads/主题-效率一览.html>
```

Token 条支持按角色和阶段查看。阶段彩虹条使用可核实的分组数据，缺项按数据契约显示未知。用户明确需要静态 SVG 时使用 `scripts/render_svg.py`。

默认将报告和最小证据 JSON 保存到用户 **Downloads**，已有同名文件时使用新文件名。打开报告核对明细展开、用量切换、数字和未知项，并检查窄屏文字。

最终回复提供报告链接和至多三条影响判断的结论。原始日志保留在原处。
